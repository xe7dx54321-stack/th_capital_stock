# SMR-D6.1 Signal Flow Truth Audit

## Overview

This document investigates the source of the mechanical, template-based risk signals appearing in the Dashboard signal flow.

## User Observed Fake Signals

```
21:18 易点天下 风险提示
...优先级已经足够高，应该先处理风险，再谈进攻。
风险监控 / 高 / 待复核 / 暂无原文 / 暂无证据包

20:18 新雷能 风险提示
还没到必须清仓，但更适合先做减仓或降权。
风险监控 / 高 / 待复核 / 暂无原文 / 暂无证据包
```

## Root Cause Analysis

### Source Location

**File**: `08_scripts/risk_engine/build_trade_risk_decision_snapshot.py`

**Code**:
```python
summary = {
    "sell": "卖出优先级已经足够高，应该先处理风险，再谈进攻。",
    "trim": "还没到必须清仓，但更适合先做减仓或降权。",
    "watch": "先盯紧，不急着做大动作。",
    "hold": "当前没有足够强的卖出信号。",
}[verdict]
```

### Timeline Analysis

The signals appear at hourly intervals (21:18, 20:18, 19:18, etc.). This is NOT real market data - it's generated by the view model:

```python
ts = now - timedelta(hours=idx + 1)  # Artificial timestamp generation
```

### Signal Generation Flow

```
SQLite risk_decision snapshot
    ↓
sell_candidates with verdict field (sell/trim/watch/hold)
    ↓
view_model generates signal with:
    - template summary based on verdict
    - artificial timestamp (now - idx hours)
    - "高" evidence_strength (hardcoded)
    - "待复核" review_status (hardcoded)
    - source_url = None
    - evidence_url = None
    ↓
Signal appears in main signal flow as "高优先级风险提示"
```

## Why These Signals Entered Main Signal Flow

1. **No Quality Gate**: Previous implementation had no data truth classification
2. **Hardcoded Strength**: All risk signals marked as "高" regardless of evidence
3. **No Evidence Check**: No validation of source_url or evidence_packet
4. **Artificial Timestamps**: Generated timestamps make signals look recent and urgent
5. **No Fallback Detection**: Template-based summaries not detected as generated content

## Quality Gate Implementation

### Changes to `signal_flow_view_model.py`

1. **Added Import**: `from data_truth_classifier import classify_data_truth, should_enter_main_signal_flow`

2. **Added Quality Check**: Each signal now classified before entering main flow

3. **Signal Filtering**:
   - `evidence_backed_real`: ALLOWED
   - `real_snapshot_with_source`: ALLOWED  
   - `real_snapshot_no_evidence`: BLOCKED by default (optional flag to include)
   - `generated_summary`: BLOCKED
   - `default_fallback`: BLOCKED
   - `placeholder`: BLOCKED
   - `historical_residual`: BLOCKED
   - `unknown`: BLOCKED

4. **New Fields**:
   - `truth_status`: Classification result
   - `truth_reason`: Why classified as such
   - `has_source`: Whether source info exists
   - `has_evidence_packet`: Whether evidence exists
   - `is_generated_summary`: Flag for generated content
   - `is_default_fallback`: Flag for fallback content

5. **Statistics**:
   - `filtered_signal_count`: Number of signals filtered out
   - `low_confidence_candidate_count`: Number of low-confidence candidates

### Changes to Tests

Three existing tests modified to use `enable_quality_gate=False`:
- `test_hot_entities_aggregation`
- `test_source_distribution_aggregation`
- `test_signal_signal_structure`

## Expected Outcome

After quality gate implementation:
- **Risk decision generated signals**: Filtered from main signal flow
- **Evidence gaps**: Filtered from main signal flow
- **Opportunity markets**: Filtered from main signal flow (no evidence)
- **Risk monitor alerts**: May still appear if they have source info
- **Strategy watch**: May still appear if they have source info
- **Daily report**: May still appear if they have evidence links
