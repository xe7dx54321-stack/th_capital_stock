## 1. 新 Dashboard 设计原则

### 核心原则
1. **老板视角优先** - 首页是投研摘要，不是工程监控
2. **页面精简** - 总页面数不超过 5 个
3. **投研语言** - 面向投研使用者，不面向开发者
4. **证据可追溯** - 所有观点必须能追溯到原始证据
5. **事实与判断分离** - 清楚区分"事实 / 证据 / 系统判断 / 待人工确认"
6. **技术字段默认隐藏** - 只保留必要的健康状态指示器
7. **不输出投资建议** - 不输出 target price、买卖建议、自动组合建议

### 视觉风格
- 白底或极浅灰底
- 深色文字（深灰/近黑）
- 少量蓝色/绿色/橙色状态点
- 卡片化布局
- 强留白
- 少装饰
- 类似高质量投研 SaaS，而非后台管理系统

## 2. 页面总数

**5 个页面**

| 序号 | 页面名称 | 定位 | 优先级 |
|---|---|---|---|
| 1 | 今日总览 | 老板首页，一屏看清今天最重要的变化 | P0 |
| 2 | 覆盖池 | 查看当前系统正在覆盖哪些公司、行业、主题 | P1 |
| 3 | 信号流 | 展示最新证据时间线 | P1 |

| 5 | 数据健康 | 只展示影响投研可靠性的关键健康状态 | P2 |

## 3. Page 1：今日总览

### 页面定位
老板首页，一屏看清今天最重要的变化。投研人员打开 Dashboard 第一眼就知道今天该关注什么。

### 一句话目标
"打开首页，30 秒内知道今天最重要的 3-5 件事。"

### 首屏布局
- **顶部状态栏**：日期 + 市场状态（A股/港股/美股最新交易日）+ 数据健康指示灯
- **英雄区**：今日最重要 3-5 条变化（卡片式，每条一句话）
- **下方分区**：
  - 公司重大动态
  - 行业主题变化
  - 投行观点/外部观点变化
  - 风险提示
  - 待人工判断事项

### 核心模块

#### 模块 1：今日最重要变化（Top Changes）
- **位置**：首屏英雄区
- **数量**：3-5 条
- **格式**：卡片列表，每条包含：
  - 变化标题（一句话）
  - 变化类型标签（公司动态 / 行业主题 / 投行观点 / 风险 / 待判断）
  - 关联公司/行业
  - 证据入口链接
  - 时间戳
- **优先级排序**：风险 > 待人工判断 > 重大公司动态 > 行业主题变化 > 观点变化

#### 模块 2：公司重大动态
- **位置**：首屏下方，左侧
- **内容**：今日有重大变化的覆盖公司
- **格式**：公司卡片列表，每张卡片：
  - 公司名称 + 代码
  - 最新变化摘要
  - 变化类型标签
  - 证据数量指示
  - 最后更新时间

#### 模块 3：行业主题变化
- **位置**：首屏下方，右侧
- **内容**：今日有显著变化的行业/主题
- **格式**：主题标签云 + 变化列表
  - 主题名称
  - 变化方向（升温 / 降温 / 新出现）
  - 关联公司数量
  - 主要催化剂摘要

#### 模块 4：风险提示
- **位置**：第二屏或折叠区
- **内容**：需要关注的风险事项
- **格式**：风险卡片，按严重程度排序
  - 风险等级（高/中/低）
  - 风险描述
  - 涉及公司/行业
  - 证据来源
  - 建议动作

#### 模块 5：待人工判断事项
- **位置**：第二屏或折叠区
- **内容**：需要人工审核/判断的事项
- **格式**：待办列表
  - 事项描述
  - 类型（审核推荐 / 确认信号 / 补证据请求）
  - 优先级
  - 截止时间（如有）
  - 快速操作按钮

#### 模块 6：数据健康简要状态
- **位置**：顶部状态栏右下角
- **内容**：3-4 个关键健康指标的状态灯
  - 行情数据新鲜度
  - 公告/新闻源状态
  - 证据 pipeline 状态
  - 整体健康度
- **交互**：点击跳转"数据健康"页

### 信息优先级
1. 风险提示（最高）
2. 待人工判断事项
3. 今日最重要变化
4. 公司重大动态
5. 行业主题变化
6. 数据健康（简要）

### 用户动作
- 点击变化卡片 → 跳转信号流（带筛选）
- 点击公司 → 跳转覆盖池（公司详情）
- 点击待判断事项 → 跳转研究队列/审核详情
- 点击健康指示灯 → 跳转数据健康页
- 点击"查看全部" → 跳转对应页面

### 空态设计
- **无数据时**：显示"今日暂无重大变化"
- **部分数据缺失**：对应模块显示"数据更新中"或"暂无数据"，不影响其他模块
- **首次使用**：显示引导文案，说明各模块用途

### 效果图绘制说明
- 首屏以卡片为主，不要堆表格
- 英雄区的 3-5 条变化要有视觉层次感（第一条最大最突出）
- 状态点用颜色区分，不要用太多图标
- 整体留白要足，不要拥挤
- 顶部状态栏要简洁，只放最关键的信息

## 4. Page 2：覆盖池

### 页面定位
查看当前系统正在覆盖哪些公司、行业、主题，以及每个对象的最新状态和证据完整度。

### 一句话目标
"一目了然知道系统在看什么，哪些看得深，哪些还缺证据。"

### 首屏布局
- **顶部筛选栏**：市场筛选（A股/港股/美股）+ 类型筛选（公司/行业/主题）+ 搜索框
- **主体区域**：Tab 切换（公司覆盖 / 行业主题覆盖）
- **默认 Tab**：公司覆盖

### 核心模块

#### 模块 1：公司覆盖池
- **格式**：卡片网格或列表（可切换视图）
- **每张卡片包含**：
  - 公司名称 + 股票代码
  - 所属行业/主题标签
  - 最新状态（正常观察 / 有新证据 / 证据偏旧 / 待补研究）
  - 证据完整度指示（进度条或点数）
  - 最近更新时间
  - 研究优先级标记
  - 快捷操作：查看详情 / 查看证据

#### 模块 2：行业主题覆盖池
- **格式**：主题卡片网格
- **每张卡片包含**：
  - 主题名称
  - 覆盖公司数量
  - 主题热度趋势（升温/稳定/降温）
  - 最近催化事件
  - 证据完整度
  - 最后更新时间

#### 模块 3：覆盖统计概览
- **位置**：页面顶部或侧边
- **内容**：
  - 总覆盖公司数
  - 总覆盖主题数
  - 证据完整高的占比
  - 需要补证据的数量
  - 今日新增覆盖

#### 模块 4：证据缺口提示
- **位置**：页面底部或折叠区
- **内容**：证据不足的公司/主题列表
- **格式**：表格，按缺口严重程度排序
  - 对象名称
  - 缺口类型（缺少财报 / 缺少研报 / 缺少公告 / 缺少新闻）
  - 建议动作
  - 优先级

### 信息优先级
1. 有新证据 / 有变化的公司（最醒目）
2. 高优先级研究对象
3. 证据不足需要补的对象
4. 正常观察的对象

### 用户动作
- 点击公司卡片 → 跳转个股详情页
- 点击主题卡片 → 跳转主题详情（未来可展开）
- 搜索框 → 按名称/代码搜索
- 筛选器 → 按市场/行业/状态筛选
- 点击"补证据" → 跳转研究队列（预填充）

### 空态设计
- **无覆盖**：显示"暂无覆盖对象"，引导添加 watchlist
- **搜索无结果**：显示"未找到匹配的公司/主题"
- **筛选无结果**：显示"当前筛选条件下暂无数据"

### 效果图绘制说明
- 卡片式布局为主，信息密度适中
- 证据完整度用进度条或小点表示，直观易懂
- 状态用颜色区分（绿色正常，黄色需关注，红色有问题）
- 搜索和筛选要醒目，是高频操作
- 可以有列表/网格视图切换

## 5. Page 3：信号流

### 页面定位
展示公司、行业、投行观点、公告、IR、新闻等最新证据的时间线。所有证据按时间倒序排列，可筛选可追溯。

### 一句话目标
"像刷信息流一样看最新证据，每条都能追到原始来源。"

### 首屏布局
- **顶部筛选栏**：
  - 来源类型筛选（全部 / 公告 / 研报 / 新闻 / IR材料 / 电话会 / 官方观点）
  - 关联对象筛选（公司 / 行业 / 主题）
  - 时间范围筛选
  - 证据强度筛选
- **主体区域**：时间线列表

### 核心模块

#### 模块 1：证据时间线
- **格式**：垂直时间线，最新的在最上面
- **每条证据卡片包含**：
  - 时间戳
  - 来源类型标签 + 来源名称
  - 证据标题/摘要
  - 关联公司/行业标签
  - 证据强度标记（强 / 中 / 弱）
  - 时间戳可信度标记
  - cannot_conclude 标记（如适用）
  - 原始来源入口链接
  - 人工审核状态（已审核 / 待审核 / 已驳回）

#### 模块 2：证据详情抽屉（点击展开）
- **内容**：
  - 完整证据内容摘要
  - 证据元数据（来源、抓取时间、处理时间）
  - 关联的其他证据
  - 系统对此证据的判断（如有）
  - 人工操作按钮（标记有用 / 标记噪声 / 加入研究队列）

#### 模块 3：信号统计概览
- **位置**：页面顶部或侧边
- **内容**：
  - 今日新增证据数
  - 各来源类型占比
  - 待审核证据数
  - 高价值证据数

### 信息优先级
1. 高价值 / 强证据（最突出）
2. 待审核的证据
3. 最新的证据
4. cannot_conclude 的证据（特殊标记）

### 用户动作
- 点击证据卡片 → 展开详情抽屉
- 点击"查看原文" → 打开原始来源（新标签页）
- 点击关联公司 → 跳转覆盖池（公司详情）
- 使用筛选器 → 按类型/对象/时间筛选
- 点击"加入研究队列" → 跳转研究队列（预填充）
- 点击"标记噪声" → 标记为低价值证据

### 空态设计
- **无证据**：显示"暂无信号数据"
- **筛选无结果**：显示"当前筛选条件下暂无信号"
- **证据加载中**：显示骨架屏

### 未来接入（opc-foundation）
- EvidencePacket → 作为新的证据类型接入时间线
- SourceObservation → 作为原始观察记录
- ExtractedDocument → 作为提取后的文档证据

### 效果图绘制说明
- 时间线设计要清晰，有时间轴视觉
- 每条证据卡片不要太高，保证一屏能看到 5-8 条
- 来源类型用小图标+文字标签区分
- 证据强度用颜色或小标记表示，不要太突兀
- 详情抽屉从右侧滑出，不跳转页面

## 6. Page 4：研究队列

### 页面定位
管理系统建议继续深挖的研究主题。投研人员在这里决定哪些主题值得深入研究，哪些可以暂缓。

### 一句话目标
"知道该研究什么，为什么研究，缺什么证据，下一步做什么。"

### 首屏布局
- **顶部筛选栏**：状态筛选（待处理 / 进行中 / 已完成 / 已暂缓）+ 优先级筛选
- **主体区域**：研究主题卡片列表（按优先级排序）

### 核心模块

#### 模块 1：待深挖主题列表
- **格式**：卡片列表，按优先级降序
- **每张卡片包含**：
  - 主题/公司名称
  - 研究优先级（高 / 中 / 低）
  - 为什么重要（一句话理由）
  - 关联公司/行业标签
  - 已有证据数量
  - 缺失证据类型
  - 下一步建议动作
  - 当前状态（待处理 / 进行中 / 已完成 / 已暂缓）
  - 创建时间

#### 模块 2：研究详情抽屉（点击展开）
- **内容**：
  - 完整的研究理由
  - 已有证据列表（可点击查看）
  - 缺失证据清单
  - 系统建议的研究路径
  - 历史操作记录
  - 人工操作按钮

#### 模块 3：人工操作区
- **操作按钮**：
  - **通过** - 确认研究，加入正式研究队列
  - **驳回** - 不研究，记录原因
  - **补证据** - 触发证据获取任务
  - **暂缓** - 先放一放，以后再看
- **备注输入**：可选，记录人工判断理由

#### 模块 4：研究统计
- **位置**：页面顶部
- **内容**：
  - 待处理数量
  - 进行中数量
  - 今日已完成数量
  - 高优先级数量

### 信息优先级
1. 高优先级待处理（最突出）
2. 中优先级待处理
3. 进行中的
4. 已暂缓/已完成（可折叠）

### 用户动作
- 点击主题卡片 → 展开详情
- 点击"通过" → 标记为进行中
- 点击"驳回" → 弹出原因输入框，确认后标记为已驳回
- 点击"补证据" → 触发证据获取任务（显示任务状态）
- 点击"暂缓" → 标记为已暂缓
- 点击已有证据 → 跳转信号流（带筛选）

### 空态设计
- **队列为空**：显示"研究队列为空，系统暂未发现需要深挖的主题"
- **无待处理**：显示"太棒了！所有待处理主题都已处理完"

### 边界注意
- 这里可以有"研究优先级"，但**不能有自动买卖建议**
- 系统只建议"研究什么"，不建议"买什么/卖什么"
- 所有判断都是研究层面的，不是投资决策

### 效果图绘制说明
- 卡片式列表，左侧是优先级标记（颜色条）
- 操作按钮在卡片底部或右侧，醒目但不干扰
- 已有/缺失证据用小图标+数字表示
- 优先级用颜色区分（红=高，黄=中，绿=低）
- 详情抽屉内容要分层，不要一屏全堆出来

## 7. Page 5：数据健康

### 页面定位
只展示影响投研可靠性的关键健康状态。不是工程日志中心，是投研人员能理解的"数据靠不靠谱"面板。

### 一句话目标
"一眼看出今天的数据能不能用来做研究，哪里有问题。"

### 首屏布局
- **顶部总览**：整体健康度评分 + 简要总结
- **主体区域**：分类健康卡片（4-6 个类别）
- **下方**：问题详情列表（blocking + degraded）

### 核心模块

#### 模块 1：整体健康度
- **位置**：页面顶部
- **内容**：
  - 整体状态（健康 / 部分降级 / 有阻塞问题）
  - 简要文字总结（一句话）
  - 最后检查时间
  - 阻塞问题数量
  - 降级问题数量

#### 模块 2：行情数据 Freshness
- **卡片内容**：
  - A股行情最新交易日 + 延迟
  - 港股行情最新交易日 + 延迟
  - 美股行情最新交易日 + 延迟
  - 状态指示灯（正常 / 延迟 / 缺失）
- **正常标准**：交易日当天收盘后 2 小时内更新

#### 模块 3：公告/IR/PDF/新闻源状态
- **卡片内容**：
  - 各数据源状态列表
  - 每个源：名称 + 最后成功抓取时间 + 状态
  - 状态分类：正常 / 延迟 / 失败 / 已降级
- **主要来源**：
  - 巨潮资讯（A股公告）
  - 港交所披露（港股公告）
  - 公司 IR 官网
  - SEC 披露（美股）
  - 研报源
  - 新闻源

#### 模块 4：Evidence Pipeline 状态
- **卡片内容**：
  - 证据处理 pipeline 各阶段状态
  - 今日处理证据数量
  - 待处理队列长度
  - 失败率
  - 状态指示灯

#### 模块 5：Foundation 输入流状态（Future Placeholder）
- **卡片内容**：
  - 当前状态：未接入（占位）
  - 未来接入后展示：
    - Foundation 连接状态
    - 最近同步时间
    - 同步的证据包数量
    - 错误率
- **视觉处理**：灰色/半透明，标注"即将接入"

#### 模块 6：问题详情列表
- **位置**：页面下方
- **分类**：
  - Blocking Issues（阻塞问题）- 红色，影响核心功能
  - Degraded Issues（降级问题）- 黄色，部分功能受影响
- **每条问题包含**：
  - 问题描述
  - 影响范围
  - 发现时间
  - 预计恢复时间（如有）
  - 相关日志入口（技术向，默认折叠）

### 信息优先级
1. Blocking Issues（最突出，红色）
2. 整体健康度
3. 行情数据新鲜度
4. 主要数据源状态
5. Degraded Issues
6. Foundation 占位

### 用户动作
- 点击健康卡片 → 展开详情
- 点击问题项 → 展开问题详情
- 点击"查看原始日志" → 打开日志文件（新标签页）
- 刷新按钮 → 手动刷新健康状态

### 空态设计
- **无健康数据**：显示"健康检查尚未运行"
- **全绿无问题**：显示"所有系统运行正常 🟢"
- **首次使用**：简要说明各指标含义

### 设计边界
- **不要做**：工程日志中心
- **不要做**：混乱的运行日志页
- **要做**：投研人员能理解的健康状态
- **要做**：明确告诉用户"今天的数据能不能用"

### 效果图绘制说明
- 大卡片布局，每个健康类别一张卡片
- 状态灯要大要明显，颜色区分清晰
- 整体健康度用大号数字+颜色表示
- 问题列表用表格，按严重程度排序
- 技术细节默认隐藏，需要时再展开

## 9. 全局设计规范

### 颜色系统
- **主色**：深蓝（#1a365d 或类似）- 用于标题、重要按钮
- **成功/正常**：绿色（#38a169）- 状态灯、正常标记
- **警告/关注**：橙色（#dd6b20）- 降级、待处理
- **危险/风险**：红色（#e53e3e）- 阻塞问题、高风险
- **中性**：深灰（#2d3748）- 正文文字
- **次要**：中灰（#718096）- 辅助文字、标签
- **背景**：白色 / 极浅灰（#f7fafc）

### 间距系统
- 卡片内边距：16-24px
- 卡片间距：16-24px
- 页面左右边距：24-32px
- 模块间距：32-48px

### 字体层级
- 页面标题：24-28px，加粗
- 模块标题：18-20px，加粗
- 卡片标题：16px，加粗
- 正文：14px，常规
- 辅助文字：12-13px，浅色

### 组件规范
- **卡片**：圆角 8px，浅边框或阴影，白底
- **按钮**：圆角 6px，主色填充或描边
- **标签**：圆角 4px，背景色+文字，小字号
- **状态灯**：小圆点（8-12px），颜色表示状态
- **进度条**：细条（4-6px高），圆角
