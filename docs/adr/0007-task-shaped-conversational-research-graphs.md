# ADR 0007：研究对话采用任务形态工作流图与持续会话状态

## 状态

建议采纳，2026-07-22。

## 背景

工作台已经具备 LLM 意图识别、确定性路由校验、个股深度研究 V3、按需采集内核和受治理记忆。但当前任务类型仍以固定流程为主，追问会被提前判定为自由对话，深度研究之外的估值建模、双标的换仓、主题筛选、产业逻辑解释和建仓信号研究缺少各自的确定性工作流与制品契约。

对 Knevo 今日连续会话的复盘显示，同一研究会话内的问题会从“双标的换仓”逐步演化为“经营驱动估值”“主题预期差筛选”“事实纠错”“产业叙事解释”和“单标的信号计划”。这些任务复用同一上下文和记忆，但需要不同的数据需求、计算方法、研究图和输出形式。继续把它们都塞进一个固定长报告，或统一降级为通用聊天，均无法稳定获得高质量结果。

## 决策

1. 保留 ADR-0004 的“LLM 主路由 + 确定性校验”，但将路由输出从单一 `intent + requiredTools` 升级为 `ResearchTaskEnvelope`：任务形态、实体集合、时间范围、用户约束、上轮依赖、期望制品、置信度和澄清状态。
2. 引入持续的 `ResearchSessionState`，保存当前研究主题、标的集合、已确认事实、可复用数据快照、模型假设、制品引用、待验证问题和用户纠错。追问必须先解析其与现有任务的关系，再决定继续、派生、修正或新建任务。
3. 不构建一条无所不包的超级工作流。使用共享研究工具和若干任务形态图组合执行：
   - 个股深度研究；
   - 经营驱动估值；
   - 双标的换仓决策；
   - 主题/产业链预期差筛选；
   - 产业逻辑与催化缺失解释；
   - 认证、产能和订单信号计划；
   - 事实纠错与依赖重算。
4. 每个任务图先生成 `DataRequirementPlan`，只获取本次结论真正需要的数据。本地新鲜数据优先；缺失或过期时由 Acquisition Kernel、正式连接器、新闻连接器和 Firecrawl 研究分支按需补证并伴随沉淀。
5. 所有数值模型必须由确定性计算服务执行，生成输入、公式、单位、版本、结果和敏感性表。LLM 只负责提出假设、解释结果和发现缺口，不得在计算服务失败后人工替代核心计算。
6. 用户纠错触发独立的 `claim_correction` 图：定位争议主张、重新取数、重算所有依赖项、生成前后差异并更新会话状态。未经重新验证，不得只靠语言承认错误后继续推演。
7. 输出采用任务制品多态：完整长报告、换仓决策备忘录、估值模型、候选矩阵、因果解释、信号清单和纠错差异报告分别定义结构与质量门。
8. 记忆分为会话工作记忆、用户投资偏好、研究事实/论点和可复用分析框架。只有候选记忆经审核后才能进入长期记忆；事实记忆必须关联证据，偏好记忆必须来自用户明确表达。
9. MVP 继续使用现有 Node 编排、Python 受治理工作流、SQLite 和进程内并行，不因“动态工作流”引入微服务、消息队列或复杂分布式调度。

## 结果

### 正面

- 用户仍可完全用自然语言交互，不需要记忆工作流名称。
- 连续追问会继承有价值的上下文，同时能为新问题切换合适的工作流。
- 数据采集和输出篇幅都由任务需求驱动，不再每次都跑同一条长流程。
- 数值推导和纠错具有可复算、可追溯的确定性。
- 现有 V3 的正式证据、引用覆盖、冲突隔离和记忆审核能力可以继续复用。

### 代价

- 需要新增任务状态、制品类型、路由评测集和跨任务依赖管理。
- 工作流数量增加后，必须维护共享工具契约，避免每个工作流各自复制数据代码。
- 会话状态与长期记忆必须严格隔离，防止临时假设被误当作已确认事实。

## 失败模式与保护

- 追问关系不明确：只询问一个会影响工作流选择的最小问题；否则按最高置信度执行并显示解释。
- 上轮数据已过期：保留上轮制品，但在继续计算前触发新鲜度检查。
- 计算服务失败：返回失败或降级为定性分析，禁止生成伪精确数字。
- 开放网页来源不可用：保留检索缺口，不用低权威材料覆盖正式事实。
- 用户纠正核心数值：冻结所有依赖结论，完成重新取数和重算后才能恢复。
- 记忆冲突：新旧版本并存并进入审核，不静默覆盖。
