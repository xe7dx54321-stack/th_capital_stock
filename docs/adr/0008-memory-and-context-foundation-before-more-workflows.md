# ADR 0008：先统一记忆与上下文，再扩展更多工作流

- 状态：建议采纳
- 日期：2026-07-28
- 决策范围：个人投研 MVP 的下一阶段

## 背景

个股深度研究 V3 已经具备真实数据补证、长流程执行、30 阶段可视化、长文综合与质量门，可以暂时作为第一条稳定的权威工作流冻结。

当前系统也已经存在三组与“记忆”有关的实现：

1. `chat_sessions/chat_messages` 保存完整会话消息；
2. `research_session_state` 保存当前任务、实体、事实、假设、制品和纠错；
3. `memory_items` 与向量库保存候选/批准研究记忆和语义索引。

但实际送给模型的上下文仍主要由前端截取最近 10 条消息组成：用户消息最多 300 字、助手消息最多 2000 字。路由器又单独截取最近 6 条、每条 300 字。系统尚无统一 token 预算、长会话压缩、重要事实固定、制品摘要引用、冲突记忆隔离和上下文快照审计。

因此，继续横向增加工作流会在每条流程中重复实现“如何理解追问、如何选择历史、如何处理纠错、如何避免超窗”的逻辑，并放大行为不一致。

## 决策

下一阶段优先建设“记忆与上下文基础设施 V1”，暂不同时扩展多条新工作流。

系统采用四层记忆，并由统一的 `ContextAssembler` 按任务和 token 预算组装：

1. **会话工作记忆**：当前任务、实体、临时假设、纠错、未决问题、最近制品；服务当前会话，可自动更新。
2. **用户偏好记忆**：用户明确表达的研究风格、风险偏好和约束；跨会话使用，但禁止从模型生成文本中猜测。
3. **研究事实与论点记忆**：绑定实体、证据、口径日期、版本和状态；只有 `approved` 可进入事实判断。
4. **分析框架记忆**：可跨标的复用的方法、传导链、核验清单；只能作为分析方法，不能冒充标的事实。

上下文组装遵循以下顺序：

1. 系统规则与当前任务契约；
2. 用户纠错、已核验事实和未决问题等固定信息；
3. 最近若干轮原文；
4. 较早会话的结构化压缩摘要；
5. 与任务匹配的已批准记忆；
6. 相关制品摘要和引用，而不是整篇报告正文；
7. 超出预算的低优先级内容明确记录为 omitted，不静默截断。

服务端数据库中的会话消息成为权威来源。前端不再负责决定哪些历史消息进入模型，只提交 `sessionId` 和当前消息。

## 关键约束

- 候选、拒绝、归档或冲突未决记忆不得进入事实判断。
- 用户纠错必须高于旧摘要和旧记忆，并触发依赖结论重算或争议标记。
- 压缩摘要只属于会话工作记忆，未经证据核验不得晋升为正式事实。
- 每次模型调用保存上下文组成、token 分配和省略原因，但不保存密钥或完整敏感请求头。
- 长报告只通过章节摘要、关键主张和 artifact 引用进入后续上下文。
- token 预算由服务端统一配置，不再由多个模块分别按字符数截断。

## 为什么不是先做更多工作流

继续做工作流能较快增加功能数量，但会让每条工作流形成自己的上下文和记忆处理方式。后续再统一时，需要同时重构路由、提示词、检索、纠错和测试，成本更高。

先做底座的直接收益是：现有深度研究报告可以被持续追问、修订和复用；随后新增的估值、事件解读、日报和组合复盘都能共享同一套上下文契约。

## 不采用的方案

### 单一向量库承载全部记忆

不采用。语义相似不等于事实有效，无法可靠处理版本、时点、证据、冲突和用户纠错。

### 把完整历史和完整报告全部塞进模型

不采用。成本和延迟不可控，重要信息会被噪声淹没，也无法解释本轮究竟用了哪些历史内容。

### 让 LLM 自由决定写入长期记忆

不采用。研究事实必须经过证据和人工审核，用户偏好必须来自用户明确表达。

## 验收后再扩展的工作流顺序

1. `thesis_update + claim_correction`：验证连续追问、事实纠错和下游重算；
2. 公告/财报事件解读：验证新证据对旧论点的增量更新；
3. `daily_brief`：验证跨实体召回与时间衰减；
4. `portfolio_review`：验证多标的、持仓约束和用户偏好；
5. 其余工作流逐条质量打磨，不再批量铺开。

## 成功标准

- 24 轮以上长会话中，实体、任务、用户纠错和未决问题不丢失；
- 页面刷新后继续追问，结果与刷新前一致；
- 核心上下文 100% 在预算内，禁止隐式字符截断；
- 候选记忆进入事实判断次数为 0；
- 旧事实与新事实冲突时，系统不静默覆盖；
- 删除会话不删除已批准研究记忆；
- 每次调用都能解释“用了什么、为什么用、哪些被省略”；
- 底座验收通过后，至少一条 `thesis_update/claim_correction` 真实链路跑通。
