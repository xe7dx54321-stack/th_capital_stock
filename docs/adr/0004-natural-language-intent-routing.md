# ADR-0004：自然语言意图路由采用“LLM 主路由 + 确定性校验”

## 状态

Accepted

## 背景

工作台以聊天为主要入口。用户不应学习工作流名称、固定句式或维护“问题—工作流”对照表。此前虽然已经存在 LLM 意图引擎，但模型不可用时只依赖分散的名称字典；实体遗漏或错配会把明确的“对某公司做深度分析”降级为自由对话。另一方面，完全依赖 LLM 也会受模型可用性、JSON 格式、提示词漂移和低置信度实体解析影响。

## 决策

采用四层路由：

1. 自动抽取证券代码、公司别名、市场和对话上下文，作为 LLM 的候选实体，不要求用户提供标准格式。
2. LLM 将自然语言解析为结构化意图，输出任务类型、实体、所需工具、置信度和是否需要澄清。
3. 确定性路由校验器核对高置信度显式请求。若用户明确表达“深度分析/研究”且唯一实体可解析，LLM 不得把请求降级为自由对话；模型不可用时同一校验器作为降级路由。
4. 当实体不唯一或不同解释会启动实质不同的工作流时，系统只追问一个最小澄清问题；不向用户暴露内部命令表。

工作流选择完成后，执行层只接受已注册任务及其允许的工具集合。`stock_deep_analysis` 固定进入受治理的 `resolve_entity → run_governed_stock_deep_dive` 主链，通用 `analyze_with_llm` 不可替代研究工作流。

## 结果

### 正面

- 用户可以自然表达需求，不依赖关键词手册。
- 明确请求在模型宕机、返回格式错误或误分类时仍能稳定启动正确工作流。
- LLM 负责语义泛化，确定性规则只承担实体主数据、硬约束和故障保护，职责清晰。
- 路由结果可记录来源与纠偏原因，便于复盘误路由。

### 负面

- 需要维护证券主数据和别名；当前 MVP 使用单一共享别名模块，后续应迁移到证券主表。
- LLM 路由与校验器可能冲突，需要持续积累真实问法作为回归样本。
- 歧义澄清需要前端和会话状态共同支持，不能只靠单次 Prompt。

## 失败模式与保护

- 模型不可用：确定性校验器继续路由高置信度请求。
- 模型把显式研究请求判为聊天：执行前校验并纠偏到研究工作流。
- 公司同名或多标的：不猜测，进入澄清。
- 实体正确但资料不足：仍生成结构完整、明确标注证据边界的报告，不返回系统状态页。
- 模型规划越权工具：执行层使用任务允许列表覆盖模型生成的任意工具链。

## 后续演进

- 将静态别名表替换为本地证券主数据表与模糊检索索引。
- 保存 `intent / entity / confidence / routing_source / correction_reason`，建立误路由评测集。
- 为多标的、时间范围、报告关注点和追问补充结构化槽位及澄清状态机。
