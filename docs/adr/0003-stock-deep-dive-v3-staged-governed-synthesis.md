# ADR-0003：采用分阶段受治理研究与模型综合写作

## 状态

Accepted

## 背景

仓库同时存在旧 JavaScript 多工具研究链和 Python V2 受治理链。前者数据面较宽但缺少证据治理、错误传播和报告校验；后者能够隔离异常字段和校验引用，但只输出事实清单与系统状态，不能满足深度研究需要。

## 决策

保留 Python 工作流作为事实、证据、计算和 artifact 的权威内核；在 Research Packet 中加入 V3 研究计划、正式披露语料、新闻、记忆、产业图谱、同行和确定性分析。Node API 在权威草稿完成后调用现有统一模型网关进行长文综合，并通过确定性质量门校验；模型不可用时返回完整受治理草稿。

V3 不恢复旧 `research-workflow.js` 为生产主链。旧实现只作为能力和交互参考。

## 结果

### 正面

- 保留现有证据闭环和运行审计能力。
- 能利用现有 MiniMax 接入生成真正的长文报告。
- 模型失败时仍有可用回退，不会只返回系统状态。
- 数据缺口按章节降级，不再阻断整份历史研究。

### 负面

- Python 与 Node 之间依赖稳定的 Packet 契约。
- 真实全链测试耗时和模型成本高于 V2。
- 需要同时维护确定性草稿和模型报告质量门。

### 中性

- V3 暂时保留 Packet schema 2.0，通过 `workflow_version` 和 `research_v3` 扩展兼容；后续对外稳定后再升级 schema major version。

## 备选方案

- 直接复活旧 JS 工作流：实现快，但重新引入无引用单次 Prompt 和伪图谱问题。
- 只扩写 Python 模板：安全，但难以达到长文分析的表达和推理质量。
- 完整多 Agent/事件图系统：能力上限高，但超出当前自用 MVP 的必要复杂度。
