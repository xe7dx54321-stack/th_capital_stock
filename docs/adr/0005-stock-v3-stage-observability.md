# ADR 0005：个股深度研究 V3 的分层进度与事件契约

## 状态

已接受，2026-07-22。

## 背景

聊天层的工作流只负责“解析证券实体”和“调用受治理深研内核”，因此它的 2/2 是真实的外层编排进度，但不能代表深研任务本身。V3 内核原先有 10 个数据库阶段，其中数据检索、确定性分析、报告生成仍被合并为大阶段；前台又只读取聊天层摘要，最终把 2/2 错标成了整个研究任务的执行步骤。

## 决策

1. 保留两层计数，禁止混用：
   - `orchestration`：聊天层的意图理解与工具编排；
   - `researchExecution`：受治理深研内核及其模型后处理。
2. `workflow_events` 是研究进度的唯一事实来源。前台不得依据静态流程图、数组长度或文案推测进度。
3. 阶段 ID 是稳定协议；中文标题、分组和展示顺序由服务端阶段目录统一提供。
4. 只有真实执行并写入 `stage.started`/`stage.completed`/`stage.warning`/`stage.failed` 的工作才计入研究阶段。不得为了视觉效果虚增步骤。
5. V3 按五组展示：研究准备、资料检索、证据与分析、报告生成、复核与归档。
6. Python 受治理流程完成后，模型综合、最终复核与覆盖写回仍属于同一个研究任务，以后处理事件追加到同一 `run_id`。这允许审计一份最终报告的完整生产链。
7. 当前 MVP 先以顺序执行获得清晰的失败隔离和可恢复性；检索分支未来可并行，但并行化不得改变阶段 ID 和事件语义。

## 结果

- 前台同时显示“研究主流程 N/N”和“意图编排 2/2”。
- 每个研究阶段可以追溯状态、消息和发生时间。
- 模型不可用、模型降级或最终校验失败不再被一个笼统的“已完成”掩盖。
- Mermaid 流程图与运行时事件可以逐项核对，而不是停留在设计文档层面。
