# 第四批：真实数据摄取可信层

## 目标

在不重写现有投研工具的前提下，让机会扫描和每日简报能够区分“最新完成交易日数据”“抓取时刻”和“陈旧数据”，保存可复核的数据快照，并对模型报告的证据引用做确定性检查。

## 方案选择

考虑过三种方案：全面重写所有数据源、只做报告后处理、在现有工具入口增加统一可信层。MVP 采用第三种。它保留已经验证过的真实数据工作流，同时把交易日、新鲜度、快照和引用校验集中在少数稳定模块中。全面重写数据源留到来源稳定性和覆盖率有真实运行数据后再做。

## 数据流

数据源工具先把响应规范化为带 `source`、`source_url`、`fetched_at`、`trade_date` 的记录。工作流执行器把每个数据工具结果封装为证据，并按市场交易日计算 `expected_trade_date` 和 `trading_session_lag`。模型只接收证据目录和数据健康门禁。模型输出后，确定性校验器检查引用编号、时效性陈述覆盖率，以及在数据不足时是否仍声称“今日/当前”。审计服务最终同时保存 Markdown 报告和 JSON 证据快照。

## 本批任务

### 任务 1：交易日历与新鲜度

- 输出：A/H/US 2026 交易日辅助函数；行情证据按已完成交易日而不是自然小时判断。
- 测试：周末、盘中、收盘后、节假日、交易日滞后。

### 任务 2：来源元数据与证据快照

- 输出：实时榜单和指数统一来源字段；每次 Agent 任务生成独立 `evidence.json` artifact。
- 测试：来源字段一致、快照大小受控、artifact 可追踪。

### 任务 3：报告引用校验

- 输出：报告生成后产生 `citationValidation`，检查未知引用、应引用陈述和被禁止的当期表述；审计与前台展示结果。
- 测试：完整引用、缺失引用、伪造引用和陈旧数据下的当期表述。

## 错误处理

可信层自身不得让数据获取结果消失。无法识别日期时标记 `undated`；快照序列化失败时保留 Markdown 报告并记录审计错误；引用校验失败先降级为警告，不自动改写模型正文，也不写入投资决策。

## 验收

机会扫描和每日简报中的行情证据能显示预期交易日与滞后交易日数；任务具有报告和证据快照两个 artifact；运行摘要能够说明引用是否完整。全部 API、UI、Python 和类型测试通过，且不调用真实模型。
